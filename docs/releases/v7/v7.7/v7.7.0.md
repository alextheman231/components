# v7.7.0 (Minor Release)

**Status**: Released

<!-- alex-c-line-release-summary-start -->
This is a new minor release of the `@alextheman/components` package. It introduces new features and other backwards-compatible changes that should require little to no refactoring. Please read the description of changes below.
<!-- alex-c-line-release-summary-end -->

## Description of Changes

<!-- user-editable-section-start -->
- Introduce a new `/v8/theme` entrypoint based on Material UI's CSS variables theming system.
  - The previous theming implementation reconstructed the entire Material UI theme whenever the colour mode changed, and required custom logic to merge default and application theme options.
  - Furthermore, we had some clunky merging logic to merge our default theme options with the provided one.
  - The new theming setup is designed to work directly with Material UI's native CSS variables and colour scheme support, reducing the amount of custom theming infrastructure required by applications.
  - The following features have been added to the new entrypoint:
    - `defaultThemeOptions`
      - Our default theme options that can be passed into the Material UI `createTheme`, and/or merged with more theme options using the `deepmerge` utility from `@mui/utils/deepmerge`.
    - `useActiveColourMode`
      - Returns the currently active colour mode, resolving the system preference when the theme is configured to use the system colour scheme.
    - `ThemeToggle`
      - Toggles between light and dark mode.

## Additional Notes

- A new entrypoint was created because this is not backwards-compatible with the previous theming and so a migration would be needed.
- The existing theming has not yet been formally deprecated as I would prefer to stabilise the new implementation first so I can provide a clearer migration guide later.
- Either way, keep an eye on the release notes for more updates.
